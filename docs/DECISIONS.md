# Decisions and known issues

- 2026-11-16: New repository. The supplementary specification was explicitly authorized by the user. Preserve the handout's academic DoDs and distinguish demo behavior from genuine model inference.
- Use a container deployment for the specified stack. Supply a local H2 development profile so Java/Python/frontend validation does not depend on a running Docker daemon. PostgreSQL remains the full-stack persistence target.
- JSON uses snake_case across services. Shared shapes are in API_CONTRACT.md; never invent alternate response fields inside individual screens.
- Only source-supported roles/topics appear in the selectable catalog. Unsupported roles fail gracefully.
- The base configuration defaults to demo, with hosted provider calls off. On 17 November the model-evidence gap was closed with the handout's suggested local Llama-3.2-3B-Instruct, avoiding dependence on hosted free credits.
- Python aliases initially failed to execute. Prefer `uv` to provision a compatible Python environment.
- Docker daemon was unavailable at initial audit. Do not claim Compose runtime verification until it actually runs.
- Docker Desktop was subsequently started successfully. The full PostgreSQL stack was built and tested, including API-restart persistence and admin import/reindex/delete. See `docs/evidence/docker-check.json`.
- Live HTTP testing caught double URI encoding in the gateway: pre-encoded query strings must use a URI builder configured with `EncodingMode.NONE`. A real HTTP-server regression test protects role names containing spaces and searches containing reserved characters.
- The execution host had a global `DEBUG` variable. Spring Boot's debug groups could enable request-body logs despite ordinary logger settings. The main entrypoint explicitly disables that flag and auth records redact their `toString()` output. Keep credentials/answers out of logs.
- BCrypt limits passwords to 72 UTF-8 bytes, not 72 characters. Enforce the byte limit before encode/matches; a Unicode-password regression test covers it.
- A running Java JAR is locked on Windows. Stop the owned local API before Maven repackage; do not interpret a packaging rename failure as a source/test failure.
- PowerShell advanced-script common parameters can consume Maven switches such as `-v`. The Maven wrapper intentionally forwards raw `$args` rather than declaring an advanced parameter block. Its version and validate paths are checked.
- Write JSON evidence using UTF-8 file APIs. PowerShell 5 redirection defaults to UTF-16 and must not be used for shared JSON artifacts.
- Actual local MiniLM weights and FAISS were exercised with 137 chunks and ten retrieval probes. Embeddings are optional local retrieval, not evidence of SLM chat inference. Serving never silently downloads weights.
- Browser test configuration reads Node's environment. Declare `@types/node` directly and include Node types in tsconfig; do not rely on incidental type packages in a developer checkout. A clean container build exposed this missing declaration.
- 2026-11-17: Public bartowski Llama-3.2-3B-Instruct Q4_K_M weights were downloaded from a pinned revision and SHA-256 verified. Retain the Llama 3.2 license and Built with Llama attribution. Store weights only in ignored `.models/` and mount them read-only.
- Pin the official llama.cpp CPU image by verified tag and digest. GitHub's v1.0.0 nightly pointer referenced a missing image tag; the checked `server-b12464` digest is recorded in compose.slm.yaml. Do not derive image identifiers without checking them.
- Readiness is not inference. ModelInfo reports configured runtime state; `mode=local_slm` and `follow_up_mode=local_slm` identify actual successful generated outputs. Interview selection and deterministic scores retain demo provenance even if a model is available.
- Local inference rejects hosted/userinfo/redirect endpoints, enforces one concurrent request and finite context/token/time budgets, and never falls back to a paid service. Missing source evidence bypasses inference; failed inference preserves original source content with an explicit warning.
- Actual generated follow-ups were saved through the gateway and reloaded, with all deterministic score fields unchanged. Follow-ups are opt-in via LOCAL_SLM_FOLLOWUPS; default source-only interview behavior keeps practice and demonstrations quick.
- Browser microphone denial and speech playback failure both preserve a visible typed-answer path. Hardware microphone accuracy remains a presentation-device check; the software does not fabricate that evidence.
- User screenshots exposed that requests for help were being scored as interview answers. The interview UI now routes clear clarification requests to persisted contextual chat, leaves scored turns unchanged, and offers Explain this feedback. Local Llama uses the saved question/reference and recent chat rather than a new keyword-only search.
- Cross-question examples needed more than a 450-byte source prefix. The local server now has a 4096-token context; chat preserves up to 1200 UTF-8 bytes of reference, bounds total input to 3200 bytes, and clips older history first. Actual ARIA tutoring and contextual examples are retained in learning-assistant evidence.
- Piper 1.8.0 with the pinned en_US-mike-medium ONNX voice provides local audio when browser voices are missing. The 63 MB voice/configuration hashes, CC0 model card and GPL engine license are retained. Speech is explicit opt-in; pause/leave cancels capture/playback and stale callbacks.
- Personal document imports accept ordinary prose and remain user-private. Shared admin Q&A import retains its original structured-bank restrictions. Do not index private document text into the shared bank or invent public URLs/licenses for personal files.
- Real Llama output wrapped valid JSON in a Markdown code fence. Accept only a complete optional JSON fence, then run the same strict count/schema/citation validation; do not mistake formatting for unavailable inference or accept arbitrary text around JSON.
- A notes-schema example placeholder encouraged examples absent from the uploaded source. Use neutral key-point placeholders and explicitly restrict examples to supplied passages. Schema/citation validation checks structure and provenance IDs, not factual accuracy; generated content still needs comparison with the source.
- Study retrieval must preserve the requested facts inside a passage. Select a bounded matching text window rather than always clipping its beginning; show that same window in the citation excerpt. A regression checks requested material near the end of a passage.
- The user requires both text and audio for interview replies and natural candidate/interviewer turns. Speech output now defaults on with mute; microphone capture still requires explicit consent. Main answers remain five scored turns, with one saved follow-up each and ungraded follow-up discussion. The visible interviewer response supplies the exact speech text, and the gateway supplies saved answer/follow-up context rather than trusting client replacements.
- Never truncate long speech silently or resume listening before its final audio chunk. Invalidate stopped/paused requests and late speech events. A recognition session ending without a final transcript must leave a visible error rather than an apparently active conversation with no microphone.
- PowerShell's default pipeline encoding can replace non-ASCII source characters with question marks. Prefer apply_patch for Unicode edits or explicitly configure UTF-8 before piping source text to Node; ordinary file write encoding alone does not fix an already lossy pipeline.
- Spoken transcripts may omit question marks and misrecognize “I don't know.” Route conservative uncertainty and question cues to contextual tutoring. Keep brief follow-up doubts in tutoring until “My answer is…” or **Ready to answer** explicitly returns to the scored turn. Persist successful local-model coaching as a separate part of the evaluation so Ava can respond to the student's actual answer and ask the saved follow-up while the rubric remains visible.
- A live alt-text tutoring reply fell back when the model emitted an unescaped quote in JSON. Use the pinned llama.cpp server's schema-constrained response format for chat and coaching, and retain validation and inference bounds in the agent. [llama.cpp server documentation](https://github.com/ggml-org/llama.cpp/blob/b12464/tools/server/README.md)
- A request comparing JavaScript and Python drew an answer about the active recipe exercise. Give the latest chat request priority over the interview prompt and carry reply scope into recent history. General replies and inference failures carry no interview citation. An explicit return uses the interview reference again. Let the model express uncertainty in the reply so a contradictory support flag cannot discard generated text. Scored coaching continues to use the reference.
- The global topic menu allowed Full Stack Security with too few matching questions. Bundle a 132-question theory bank and derive setup choices from role, topic, and difficulty counts. Retire coding exercises from the active bank and preserve stored interview snapshots. Prompt students to start a theory interview if an unanswered question has been retired.
- Private study notes were capped at two sentences and three bullets, and the Markdown export echoed the request and raw citation metadata. Spread overview retrieval across the document, prioritize distinct topic terms for focused retrieval, and use schema-constrained, cited sections. A live multi-section request hit the 30-second model deadline, so allow 39 seconds for study generation inside the 45-second gateway limit. Keep additional source details available and export Markdown with numbered references. [llama.cpp schema documentation](https://github.com/ggml-org/llama.cpp/blob/b12464/tools/server/README.md#post-v1chatcompletions-openai-compatible-chat-completions)
- The user requested Word downloads for study materials. Generate actual DOCX files in the browser from saved results, with Word headings and numbered citations. This requires no additional request with private document data. [DOCX browser export documentation](https://docx.js.org/api/classes/index.Packer.html#toblob)
- The user requested a white-first workspace with one blue accent. Keep the existing React, Vite, and Tailwind stack and move the redesign into shared surface, spacing, and typography styles. Put interview setup and actual practice activity first on the overview, use compact topic rows in the library, and place the current question before the avatar and answer form on small screens.
- Keep the general AVA interview in AI Interview. Feedback and Analytics share a navigation entry and retain their separate route hashes. Resume Mock is a separate owner-scoped interview with five cited passages, one follow-up per question, and saved ungraded responses. Reuse personal document parsing without indexing resume data or retaining the uploaded file.
- Use the existing private local model for Java, JavaScript, and Python coaching. JavaScript execution runs in a memory-limited QuickJS WebAssembly guest inside a short-lived Worker. Keep the WebAssembly CSP exception on the dedicated Worker response and preserve the application page policy.
